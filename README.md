# winFlexCrypto — современная криптография для 1С:Предприятие

Внешняя компонента Native API для 1С:Предприятие 8.3: электронная подпись **Ed25519**, шифрование на открытый ключ
(**sealed box** libsodium: X25519 + XSalsa20-Poly1305), шифрование паролем (**Argon2id + XChaCha20-Poly1305**),
SHA-256 и криптостойкие случайные числа. Без КриптоПро, без сертификатов и без установки чего-либо в ОС.

- **совместима с libsodium и PyNaCl байт в байт** — подписи и конверты проверяются и вскрываются на Python, Go,
  JavaScript, PHP (libsodium есть почти везде); совместимость проверена тестовыми векторами `testdata/vectors.json`;
- Windows и Linux, x86 и x64 (пакет один на все четыре платформы);
- написана на Rust на библиотеках [RustCrypto](https://github.com/RustCrypto) и [addin1c](https://github.com/medigor/addin1c);
- лицензия MIT.

*English: 1C:Enterprise 8.3 Native API add-in: Ed25519 signatures, libsodium sealed boxes (X25519 +
XSalsa20-Poly1305), password encryption (Argon2id + XChaCha20-Poly1305), SHA-256, OS CSPRNG. Byte-compatible
with libsodium / PyNaCl. Windows/Linux, x86/x64. Written in Rust. MIT.*

## Зачем

Встроенный `МенеджерКриптографии` 1С работает через криптопровайдер ОС и сертификаты X.509: для обмена с
партнёрами на ГОСТ это правильно, но для задач «зашифровать выгрузку для конкретного получателя»,
«подписать задание и проверить его в другой базе», «хранить секрет под паролем» нужен провайдер, сертификаты,
одинаковая настройка на всех серверах и Linux. winFlexCrypto даёт эти операции одним ZIP-макетом: ключ — 32 байта
в строке base64, которые хранятся в константе или справочнике.

## Быстрый старт

1. Скачайте `winFlexCrypto.zip` из [Releases](../../releases) (MANIFEST.XML + 4 библиотеки).
2. Добавьте общий макет `winFlexCrypto` типа «Двоичные данные» и загрузите в него ZIP.
3. Подключите:

```bsl
ПодключитьВнешнююКомпоненту("ОбщийМакет.winFlexCrypto", "winFlex", ТипВнешнейКомпоненты.Native);
Крипто = Новый("AddIn.winFlex.Crypto");

// Ключи получателя: JSON {sign_secret, sign_public, box_secret, box_public}, всё base64.
Ключи = Крипто.СоздатьКлючи();
Открытые = Крипто.ОткрытыеКлючи(Ключи);        // без секретов — это отдают отправителю

// Отправитель: шифрует на открытый ключ получателя.
Конверт = Крипто.ЗашифроватьДля(ДанныеВыгрузки, ОткрытыйКлючШифрования);
// Получатель: расшифровывает своим секретным ключом.
Данные = Крипто.Расшифровать(Конверт, СекретныйКлючШифрования);

// Подпись и проверка.
Подпись = Крипто.Подписать(Данные, СекретныйКлючПодписи);
Верно = Крипто.ПроверитьПодпись(Данные, Подпись, ОткрытыйКлючПодписи);

// Секрет под паролем.
Шифр = Крипто.ЗашифроватьПаролем("секрет", Пароль);
Секрет = ПолучитьСтрокуИзДвоичныхДанных(Крипто.РасшифроватьПаролем(Шифр, Пароль));
```

В клиенте компоненту один раз устанавливают (`НачатьУстановкуВнешнейКомпоненты`). Для секретных ключей лучше
серверный контекст: ключ не покидает сервер.

## API

Объект `AddIn.winFlex.Crypto`. Имена методов — русские и английские, регистр не важен. Все методы — функции.

| Метод | Параметры | Результат |
|---|---|---|
| `СоздатьКлючи()` / `GenerateKeys` | — | Строка JSON: `sign_secret`, `sign_public` (Ed25519), `box_secret`, `box_public` (X25519), base64 |
| `ОткрытыеКлючи(КлючиJSON)` / `PublicKeys` | JSON набора | JSON `sign_public`, `box_public`; проверяет, что открытые части соответствуют секретным |
| `Подписать(Данные, СекретныйКлючПодписи)` / `Sign` | | ДвоичныеДанные, 64 байта (Ed25519) |
| `ПроверитьПодпись(Данные, Подпись, ОткрытыйКлючПодписи)` / `Verify` | | Булево |
| `ЗашифроватьДля(Данные, ОткрытыйКлючШифрования)` / `Seal` | | ДвоичныеДанные: конверт, данные + 48 байт |
| `Расшифровать(Конверт, СекретныйКлючШифрования)` / `Unseal` | | ДвоичныеДанные |
| `ЗашифроватьПаролем(Данные, Пароль)` / `EncryptWithPassword` | | ДвоичныеДанные, формат `WFC1` |
| `РасшифроватьПаролем(Шифр, Пароль)` / `DecryptWithPassword` | | ДвоичныеДанные |
| `SHA256(Данные)` | | ДвоичныеДанные, 32 байта |
| `СлучайныеБайты(Количество)` / `RandomBytes` | до 1 МБ | ДвоичныеДанные из генератора ОС |
| `Отпечаток(ОткрытыйКлючПодписи, ОткрытыйКлючШифрования)` / `Fingerprint` | | Строка `XXXX-XXXX-XXXX-XXXX-XXXX` — сверить ключ голосом или в письме |
| `Версия()` / `Version` | | Строка |

Свойство `ОписаниеОшибки` / `LastError` — причина последней ошибки. При ошибке метод вызывает исключение
в 1С, текст причины — в этом свойстве (по-русски).

Параметры:
- **данные** — `ДвоичныеДанные` или `Строка` (строка кодируется в UTF-8 без BOM);
- **ключи, подписи, конверты, шифры** — `ДвоичныеДанные` или строка base64 (переносы строк, которые 1С вставляет
  в длинный base64, допускаются).

## Форматы

| Что | Формат | Совместимо с |
|---|---|---|
| Подпись | Ed25519 (RFC 8032), 64 байта; секретный ключ — 32-байтовое зерно; проверка строгая (`verify_strict`) | libsodium `crypto_sign_detached`, PyNaCl `SigningKey`, Go `crypto/ed25519`, OpenSSL |
| Конверт | libsodium sealed box: эфемерный X25519 + XSalsa20-Poly1305, `эфемерный ключ (32) ‖ шифр ‖ тег (16)` | libsodium `crypto_box_seal`, PyNaCl `SealedBox`, libsodium.js |
| Шифр паролем | `WFC1 ‖ m_cost u32 LE ‖ t_cost u32 LE ‖ p_cost u32 LE ‖ соль[16] ‖ nonce[24] ‖ шифр+тег`; Argon2id v1.3 (по умолчанию 64 МиБ, 3 прохода, 1 поток — рекомендация OWASP), XChaCha20-Poly1305, заголовок — связанные данные AEAD | любая реализация Argon2id + XChaCha20-Poly1305 (формат описан здесь) |
| Отпечаток | первые 10 байт SHA-256(`sign_public ‖ box_public`), hex по 4 символа через дефис | — |

Пример проверки на Python (PyNaCl):

```python
from nacl.signing import VerifyKey
from nacl.public import PrivateKey, SealedBox
import base64
VerifyKey(base64.b64decode(sign_public)).verify(data, signature)        # подпись из 1С
SealedBox(PrivateKey(base64.b64decode(box_secret))).decrypt(envelope)   # конверт из 1С
```

## Сборка из исходников

Нужны [Rust](https://rustup.rs) (stable), [cargo-zigbuild](https://github.com/rust-cross/cargo-zigbuild) и zig
(`pip install ziglang cargo-zigbuild`) — одна машина Windows собирает все 4 цели:

```bat
build.cmd test --release          & rem тесты Rust, в т.ч. векторы libsodium/PyNaCl
python package.py                 & rem dist\winFlexCrypto.zip: win32/win64 (GNU), linux x86/x64 (glibc 2.17+)
```

`build.cmd` берёт Rust из `C:\rust` (`RUSTUP_HOME`, `CARGO_HOME`) и zig из пакета Python `ziglang` — пути
переопределяются переменными окружения. Из DLL экспортируются только 5 функций Native API (`exports.def`).
Rust std требует Windows 10 / Server 2016 и новее.

## Проверка

- Rust: `build.cmd test --release` — 10 тестов: ключи, подпись, конверт и отпечаток совпадают с эталоном PyNaCl
  (`testdata/vectors.json`), шифрование паролем, отказ на чужом ключе и испорченных данных.
- 1С: обработка `test/1c/src/WFCТестыКомпоненты` для [Vanessa-ADD](https://github.com/vanessa-opensource/add)
  (xUnit, серверный контекст). `python test\1c\make_src.py` кладёт в её макеты собранный ZIP и векторы, затем
  обработку собирают (`vrunner compile` или конфигуратор) и запускают xddTestRunner.

Проверено на 1С:Предприятие 8.3.27, сервер Windows x64: Rust — 10 из 10, 1С — 10 из 10. Сборки x86 и Linux
проверены статически (экспорт функций); в клиенте компонента подключается так же, как любая Native-компонента.

## Безопасность

- Секретные ключи храните там, где их не прочитают пользователи: константа или регистр с доступом только
  на сервере, лучше — зашифрованными паролем (`ЗашифроватьПаролем`).
- Конверт не подписан: получатель не знает, кто его отправил. Если это важно — подпишите данные (или конверт)
  ключом отправителя и проверьте подпись.
- Компонента не хранит ключи и состояние между вызовами, не ходит в сеть, не пишет на диск.
